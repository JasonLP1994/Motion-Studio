# Finish the iart-ai pack, then fill gaps by hand

The skills most worth adding to Motion Studio come from the **same MIT-licensed iart-ai collection the studio already trusts**: beat-sync-editing, logo-animation and color-motion (the rest of the motion-design pack that supplied motion-art-direction and shot-composition), plus iart-ai's kinetic-typography skill. Add one Remotion-native transition pack (ashad001/remotion-transitions, MIT, docs only) alongside them. Together these five fill the clearest gaps (cutting to music, logo stings, colour and grading, type in motion, punchy scene changes) without paid services, telemetry or a second rendering engine. A second wave covers specialist looks: shaders (gokayfem/shader-skills), 3D determinism (iart-ai webgl-animation-skills plus selected CloudAI-X three.js skills), generative art (Anthropic's algorithmic-art, adapted), lower thirds and countdowns, and the video-shotcraft shot library. Each of these needs a short local "Remotion override" note, because almost none of them was written for frame-by-frame rendering. Three gaps are better filled by short studio-written notes than by any outside skill: SVG path drawing and morphing with Remotion's own `@remotion/paths`, audio-reactive visuals with `@remotion/media-utils`, and LUT colour grading as a single ffmpeg pass. Most of what the big curated lists offer for "video" is either a paid generation API (fal, Sora, Runway, MiniMax, HeyGen) or a real-time web animation library (Motion, anime.js, web GSAP) that clashes with Remotion's rule that time = frame / fps, so most of the catalogue is a skip. All findings are as of 2026-11-10. The GitHub API, skills.sh and remotion.dev were blocked during research, so last-commit dates are mostly unverified and some licences rest only on registry listings. These gaps are flagged below.

## Five additions cover the biggest gaps first

In plain terms: the studio can already plan, caption, cut shorts, separate people from backgrounds, add sound and build three kinds of explainer. What it lacks is know-how for **timing edits to music, animating logos, handling colour properly, making words move expressively, and transitions with more punch than a fade or slide**. Each pick below is a folder of Markdown instructions that you copy into `.claude/skills/` by hand. None needs an account or an API key.

The first three complete a pack the studio already half-owns. motion-design-skills is **MIT, 218 stars, and lists animation-principles, color-motion, shot-composition, motion-art-direction, after-effects, beat-sync-editing, remotion-video, logo-animation and motion-background** ([README](https://raw.githubusercontent.com/iart-ai/motion-design-skills/main/README.md); [iart-ai org](https://github.com/orgs/iart-ai/repositories)). One caution applies to the whole iart-ai family. Only the kinetic-typography SKILL.md was read in full, so **whether the color-motion, logo-animation and beat-sync-editing folders contain scripts is unverified**. ## Notes disagreed on four points, and the primary files settle them

The research came from four separate notes, and their conflicts are worth resolving openly because they change the recommendations.

**Kinetic typography.** The animation-libraries note concluded that "searches for a dedicated 'kinetic typography' agent skill returned none". The curated-lists note listed iart-ai/kinetic-typography-skills (MIT, 24 stars, updated 22 June 2026) and actually read its SKILL.md and README from GitHub ([README](https://raw.githubusercontent.com/iart-ai/kinetic-typography-skills/main/README.md)). The second note read the primary files, so it wins: **a dedicated kinetic-typography skill exists and is verified** (licence file, README and SKILL.md all read). The first note's search missed it. What remains unverified is whether its helper scripts make any network calls. The other kinetic-type lead, hugobowne/remotion-video ("motion grammar, kinetic typography, character moments"), could not be resolved on jsDelivr, so its licence and contents are **unverified** ([TypingMind listing](https://www.typingmind.com/skills/hugobowne-remotion-video)).

**GSAP skills.** One note rated the official greensock/gsap-skills "maybe (cherry-pick gsap-plugins and gsap-timeline)"; another rated it "skip for a Remotion studio". Both agree on the facts: the skill text is MIT ([LICENSE](https://cdn.jsdelivr.net/gh/greensock/gsap-skills@main/LICENSE)), the GSAP library itself uses a proprietary "Standard 'no charge' license" ([npm](https://registry.npmjs.org/gsap)), and neither skill file mentions Remotion or per-frame seeking ([gsap-timeline](https://cdn.jsdelivr.net/gh/greensock/gsap-skills@main/skills/gsap-timeline/SKILL.md)). The reconciled verdict is **skip as an installed skill, keep as reading material**. The technique catalogue (SplitText, DrawSVG, MorphSVG's `shapeIndex`) is worth borrowing, but it can be rebuilt with `interpolate` and `@remotion/paths`, and the README tells agents to "recommend GSAP" by default ([README](https://raw.githubusercontent.com/greensock/gsap-skills/main/README.md)). That steering would pull a beginner's agent off Remotion.

**digitalsamba/claude-code-video-toolkit.** The notes give different sizes (412 files in one, about 2.5k stars and 511 commits in another). These are different measures, not a contradiction. All the notes agree it is MIT and Remotion-based, and that it bundles ElevenLabs, Modal, RunPod, Ideogram, Cloudflare R2 and a `youtube_upload` tool ([GitHub](https://github.com/digitalsamba/claude-code-video-toolkit); [file listing](https://data.jsdelivr.com/v1/packages/gh/digitalsamba/claude-code-video-toolkit@main?structure=flat)). The reconciled verdict is **skip the pack, and at most copy its `playwright-recording` skill after reading it**. The upload and cloud-storage tools also brush against the rule that finished videos never leave the machine for GitHub or other hosts.

**OpenMontage.** One note verified **AGPL-3.0** from the LICENSE file ([README](https://raw.githubusercontent.com/calesthio/OpenMontage/main/README.md)). Another called the licence unverified and flagged an aggregator's 43k-star figure as implausible ([vibeindex](https://www.vibeindex.ai/skills/calesthio/openmontage/ffmpeg)). The LICENSE read wins, and the copyleft licence alone makes it a skip under the studio's permissive-licence preference.

Smaller rating differences (motion-background "add" vs "maybe", iart-ai after-effects "skip" vs "maybe", diffusionstudio/lottie "add" vs "maybe") are resolved in the tables below. In each case the lower rating wins where the skill overlaps something the studio already has.

beat-sync-editing is about cutting *to* music, not animating *from* it. For true audio-reactive visuals (bars, pulses, shapes that throb on the kick), Remotion's own `@remotion/media-utils` provides the parts. `visualizeAudio()` returns an amplitude array with bass at index 0 and needs a power-of-two sample count ([Remotion docs](https://www.remotion.dev/docs/visualize-audio)). `useWindowedAudioData()` loads only the audio around the current frame for long tracks ([Remotion docs](https://www.remotion.dev/docs/use-windowed-audio-data)). Remotion has **no built-in beat-detection API**, so beats come from thresholding the low band yourself ([Remotion docs](https://www.remotion.dev/docs/audio-visualization)). No well-established Remotion beat-detection skill exists, so a studio-written template that wraps these two functions with a bass-threshold helper, and reuses sound-effects' beat-grid check, is the cleanest addition. These API details come from search snippets because remotion.dev was blocked, so confirm them with `remotion-docs` first.

### Curated lists: useful for discovery, none audits security

The four main lists vet lightly. hesreallyhim/awesome-claude-code's bot "is a mechanical form-validator, it does not review the quality of the recommended resource", with a 100-star bar and paywalls as blockers ([CONTRIBUTING](https://raw.githubusercontent.com/hesreallyhim/awesome-claude-code/main/CONTRIBUTING.md)). travisvn/awesome-claude-skills closes PRs under 10 stars and rejects "SaaS Wrappers", the closest match to the studio's no-paid-services stance ([CONTRIBUTING](https://raw.githubusercontent.com/travisvn/awesome-claude-skills/main/CONTRIBUTING.md)). VoltAgent/awesome-agent-skills (MIT) is the broadest index of official vendor skills, but most of its video entries are paid APIs: openai/sora, fal-ai, MiniMax, Venice ([README](https://raw.githubusercontent.com/VoltAgent/awesome-agent-skills/main/README.md)). ComposioHQ's list is vendor-run and mostly promotes Composio automations ([README](https://raw.githubusercontent.com/ComposioHQ/awesome-claude-skills/master/README.md)). skills.sh, the registry behind `npx skills add`, was unreachable, and HyperFrames notes it "can lag `main` by hours" ([HyperFrames README](https://raw.githubusercontent.com/heygen-com/hyperframes/main/README.md)). That is one more reason to copy folders from a pinned commit instead.

Two vendor findings close the loop. **Only LottieFiles and GreenSock publish official motion skills.** Nothing official exists from Rive, Spline, Jitter, Cavalry, Motion Canvas or Revideo. Motion Canvas has only a third-party pack (videozero/skills, Apache-2.0, different runtime) ([README](https://raw.githubusercontent.com/videozero/skills/main/README.md)). HyperFrames publishes nine skills, all tied to its own HTML+GSAP runtime, Node 22 and paid "Pro" tiers ([README](https://raw.githubusercontent.com/heygen-com/hyperframes/main/README.md)). The studio already holds the useful part, the craft references, so install none of them. Its 450-block registry is at most a visual reference for Remotion rebuilds.

## Every outside skill needs a short Remotion override before it runs

Almost every candidate breaks at least one studio rule out of the box, so how you install matters as much as what you install. Copy each chosen folder by hand from a pinned commit into `.claude/skills/`, instead of running `npx skills add` or `/plugin marketplace add`. Those commands run an installer, use the network, may write to `~/.claude/skills` outside the workspace, and some need Node 22.20 or later ([gokayfem README](https://raw.githubusercontent.com/gokayfem/shader-skills/main/README.md)). Then add a few lines at the top of each copied SKILL.md, the same way the studio already adapts its iart-ai skills.

The override text is the same for nearly every skill. In Remotion: time = frame / fps, with no `useFrame`, `requestAnimationFrame`, `Date.now()`, clocks or timers. Use `mixer.setTime(frame / fps)` for 3D clips. Seed every random number. Re-step simulations from frame 0 with a fixed timestep, or memoise by frame, because Remotion renders frames out of order and in parallel. Import libraries from `node_modules`, never from a CDN or importmap. Render WebGL with `gl=angle`. Never run `npx playwright install`; use `require('playwright')`. Strip iart.ai and Anthropic branding defaults, and keep all words, colours and timings in the one config file.

Specific conflicts to override: iart-ai's WebGL skills suggest CDN importmaps and `npx playwright screenshot` ([threejs-animation](https://raw.githubusercontent.com/iart-ai/webgl-animation-skills/main/skills/threejs-animation/SKILL.md)). algorithmic-art loads p5.js from cdnjs and mandates Anthropic fonts ([SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/SKILL.md)). canvas-design says to download fonts freely ([SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/canvas-design/SKILL.md)). CloudAI-X's R3F skill teaches `frameloop` ([SKILL.md](https://raw.githubusercontent.com/CloudAI-X/threejs-skills/main/skills/threejs-react-three-fiber/SKILL.md)). gokayfem's checker wants glslangValidator, a system install that needs your permission first. Under CLAUDE.md's rules, ask before any install outside the folder (glslangValidator, a global capcut-cli, Puppeteer). Keep renders out of any repo the skills came from, and skip any tool that uploads (digitalsamba's `youtube_upload` and R2 storage).

On licences: everything recommended as "add" is MIT or Apache-2.0, verified from its LICENSE file. Two dependency-level caveats remain. GSAP is free but proprietary, and Remotion's own `@remotion/transitions` carries the Remotion licence rather than an OSI one ([npm](https://registry.npmjs.org/@remotion%2Ftransitions)). Neither blocks the plan, but you should know about both.

## Conclusion

The research changes the question from "which skill pack should we install?" to "which few instruction files fill real gaps, and what do we write ourselves?" The useful supply is narrow and concentrated: one trusted MIT publisher (iart-ai) covers most new craft areas, and only one transition pack, one shader library and two 3D packs show real care about deterministic, seekable rendering. Everything that sells itself as a complete "AI video" system either rents a paid model or runs on a real-time clock that Remotion cannot use. The three most valuable additions (SVG paths, audio-reactive visuals and LUT grading) are not third-party skills at all. They are short studio notes over tools the studio already has installed, and the grep showing no installed skill mentions `@remotion/paths` is a reminder that documentation, not capability, is the bottleneck.

Two things are still unknown and worth checking before the second wave: whether the iart-ai pack folders and gokayfem's scripts make network calls (only read in part), and whether diffusionstudio's Lottie output and the GSAP seek pattern actually render frame-accurately in this Remotion setup. A single test render for each would settle them. Because no curated list audits security, the studio's habit of reading every folder before copying it is the only real safeguard. Adding a DON'T line against side-panel teaching cards before trying any explainer-style skill keeps the deleted look from coming back.
