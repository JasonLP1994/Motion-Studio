Any new skill must add more than this.

## What exactly do Anthropic's algorithmic-art and canvas-design skills contain, what licence are they under, and how could they adapt to Remotion?

### Takeaway
Both are Apache-2.0 instruction-only skills that follow a "philosophy first, then express it" workflow. algorithmic-art produces a seeded p5.js HTML viewer. canvas-design produces a static PNG/PDF. Neither renders video or knows about Remotion. Their value is the creative method and the seeded-randomness discipline, which port cleanly into a frame-driven React component.

### Cited Findings
- Each skill folder has its own LICENSE.txt containing the full Apache License 2.0 text, with "Copyright 2026 Anthropic, PBC." The algorithmic-art and canvas-design licence files are byte-identical — [algorithmic-art LICENSE.txt](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/LICENSE.txt), [canvas-design LICENSE.txt](https://raw.githubusercontent.com/anthropics/skills/main/skills/canvas-design/LICENSE.txt)
- The current README says: "Many skills in this repo are open source (Apache 2.0)," and that the document skills (docx, pdf, pptx, xlsx) "are also open source (Apache 2.0)." The docx LICENSE.txt is now Apache-2.0 too (the template copyright line is not filled in). This replaces the earlier proprietary/source-available wording for document skills that the brief mentions — [anthropics/skills README](https://raw.githubusercontent.com/anthropics/skills/main/README.md), [docx LICENSE.txt](https://raw.githubusercontent.com/anthropics/skills/main/skills/docx/LICENSE.txt)
- The repo also has THIRD_PARTY_NOTICES.md listing BSD-2-Clause and GPL-3.0 components. These appear to relate to bundled tooling, not the two art skills (I didn't check which files they cover) — [THIRD_PARTY_NOTICES.md](https://raw.githubusercontent.com/anthropics/skills/main/THIRD_PARTY_NOTICES.md)
- Path history for algorithmic-art: Dec 1 2025 ("Move example skills into dedicated folder…", #129), then Apr 20 2026 ("Fill in Apache 2.0 copyright notice…", #990). The content is essentially unchanged since late 2025 — [GitHub commits](https://github.com/anthropics/skills/commits/main/skills/algorithmic-art)
- Installed as the `example-skills` plugin via `/plugin marketplace add anthropics/skills` — [README](https://raw.githubusercontent.com/anthropics/skills/main/README.md)
- algorithmic-art description: "Creating algorithmic art using p5.js with seeded randomness and interactive parameter exploration… flow fields, or particle systems." Step 1 writes a 4–6 paragraph "algorithmic philosophy" (.md). Step 2 writes p5.js art "90% algorithmic generation, 10% essential parameters" — [algorithmic-art SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/SKILL.md)
- It requires `randomSeed(seed); noiseSeed(seed);` ("Same seed ALWAYS produces identical output"), a `params` object of quantities, scales, probabilities, ratios, angles and thresholds, and a "deduced conceptual seed" (a subtle reference woven into the parameters) — [SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/SKILL.md)
- It mandates starting from `templates/viewer.html` and keeping "Anthropic branding (Poppins/Lora fonts, light colors, gradient backdrop)." p5.js loads from `cdnjs.cloudflare.com/ajax/libs/p5.js/1.7.0`. Bundled resources: `templates/viewer.html` and `templates/generator_template.js` — [SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/SKILL.md)
- generator_template.js uses `randomSeed(seed)` and defaults to `noLoop()` for static art. Animation is through p5's `draw()` loop (wall-clock and frame-loop based, not seekable) — [generator_template.js](https://raw.githubusercontent.com/anthropics/skills/main/skills/algorithmic-art/templates/generator_template.js)
- canvas-design: "Create beautiful visual art in .png and .pdf documents using design philosophy… poster, piece of art, design, or other static piece." The same two-step method applies, with "90% visual design, 10% essential text" — [canvas-design SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/canvas-design/SKILL.md)
- canvas-design tells the agent to use fonts from its `./canvas-fonts` directory, and also to "Download and use whatever fonts are needed." It has strict layout rules: "nothing falls off the page and nothing overlaps," and refine rather than add ("If the instinct is to call a new function or draw a new shape, STOP") — [canvas-design SKILL.md](https://raw.githubusercontent.com/anthropics/skills/main/skills/canvas-design/SKILL.md)

### Inferences
- Adapting to Remotion: keep the philosophy step and the seed/params discipline. Replace the p5 `draw()` loop with a pure function `render(frame, params, seed)`. Draw to a `<canvas>` (2D or WebGL) inside a component that redraws from `useCurrentFrame()`. Simulations (flow-field trails, particle accumulation) must be re-stepped deterministically from frame 0 up to the current frame with a fixed timestep, or cached by frame, because Remotion renders frames out of order and in parallel. Keep `params` in the studio's single config file to match its "one config file" rule.
- The viewer.html branding rule (Anthropic fonts and colours) should be removed or overridden in a local copy. It conflicts with the studio's per-video art direction.
- canvas-design's "download whatever fonts" line conflicts with the studio's "ask before installing anything outside this folder" spirit. A local override should restrict it to bundled or Google fonts already in `public/`.
- canvas-design is most useful for poster frames, thumbnails and end cards (still outputs), and as a composition/restraint guide. It adds little to motion.

- I didn't list canvas-fonts licences (GitHub directory pages were blocked; the fonts are probably OFL, but that is unverified).
- I didn't fetch canvas-design's own path commit history.

## Are there Three.js / R3F / @remotion/three agent skills with good guidance for deterministic, frame-based rendering?

### Takeaway
No community skill targets `@remotion/three` specifically. Remotion's own 3d.md rule (already installed) has the essential constraints but is thin. The best add-ons are CloudAI-X/threejs-skills (current, verified three r186 / R3F 9 API) and iart-ai's threejs-animation and particle-system (the strongest determinism guidance found). Both need a local "Remotion override" note, because they teach `useFrame` / `clock` loops.

### Cited Findings
- Remotion docs: `<ThreeCanvas />` "will allow you to use useCurrentFrame() and other Remotion hooks within a R3F Canvas. Animations are now not inside a useFrame() hook." Three.js "does not render with the default OpenGL renderer – we recommend to set it to angle" (`Config.setChromiumOpenGlRenderer('angle')`, or `chromiumOptions: { gl: "angle" }` for SSR) — [Remotion docs: @remotion/three](https://www.remotion.dev/docs/three)
- CloudAI-X/threejs-skills targets "three.js r186 (`three@0.186`), React Three Fiber 9.8 with drei 10.7, and gltf-transform 4.5." It lists API changes between r160 and r186 (`RGBELoader`→`HDRLoader`, `Clock`→`Timer`, `PostProcessing`→`RenderPipeline`, WebGL 1 removed) and has a Common Mistakes list in each skill — [CloudAI-X README](https://raw.githubusercontent.com/CloudAI-X/threejs-skills/main/README.md)
- Its 13 skills: fundamentals, geometry, materials, lighting, textures, animation, loaders, shaders, postprocessing, interaction, performance, react-three-fiber, asset-pipeline. Last commits are Oct 19 2026 (added the performance, R3F and asset-pipeline skills). ## Are there shader/GLSL agent skills, and are any compatible with Remotion?

### Takeaway
Yes. gokayfem/shader-skills (MIT, v2.0.0, Oct 2026) is the most rigorous: a tested GLSL library, bundler and checker. MiniMax shader-dev (MIT) and iart-ai shader-glsl (MIT) are lighter, docs-only options. All produce Shadertoy-style or ShaderMaterial fragment shaders. These work in Remotion if time is passed as a uniform from `useCurrentFrame()`, through the installed `createEffect()` WebGL2 path or a `<ThreeCanvas>` full-screen quad.

### Cited Findings
- gokayfem/shader-skills: "186 GLSL functions in 20 modules, a dependency bundler, a checker and 11 ready-to-run Shadertoy examples." It covers SDF raymarching, terrain, water, clouds and generative art. "Every SDF is checked on the GPU." The checker "catches WebGL1 leftovers, sine hashes… and compiles with glslangValidator." It flags "sine hashes that differ per GPU" as a known agent error — [README](https://raw.githubusercontent.com/gokayfem/shader-skills/main/README.md)
- Install: `claude plugin marketplace add gokayfem/shader-skills`, or copy `skills/shader-art-coding`. The skills CLI "requires Node.js 22.20 or later." Release: v2.0.0. Last commits Oct 23 2026. Licence: MIT — [README](https://raw.githubusercontent.com/gokayfem/shader-skills/main/README.md), [commits](https://github.com/gokayfem/shader-skills/commits/main), [LICENSE](https://raw.githubusercontent.com/gokayfem/shader-skills/main/LICENSE)
- It also ships a "video-to-shader prompt" and a merged PR "video-acceptance-checks" (Oct 19 2026) — [README](https://raw.githubusercontent.com/gokayfem/shader-skills/main/README.md), [commits](https://github.com/gokayfem/shader-skills/commits/main)
- MiniMax shader-dev: "A unified skill covering 36 GLSL shader techniques (ShaderToy-compatible)" (ray marching, SDF, fluid, particles, procedural, lighting, post-processing). Frontmatter `license: MIT`, version 1.0. One commit, Mar 17 2026 — [shader-dev SKILL.md](https://raw.githubusercontent.com/MiniMax-AI/skills/main/skills/shader-dev/SKILL.md), [commits](https://github.com/MiniMax-AI/skills/commits/main/skills/shader-dev), [LICENSE](https://raw.githubusercontent.com/MiniMax-AI/skills/main/LICENSE)
- iart-ai shader-glsl: gradients, noise/fbm, SDFs, domain warping, image transitions, and Three.js ShaderMaterial wiring. "The shader is a pure function of uniforms — drive everything from `u_time` (and `u_progress` for transitions)." In-shader randomness uses a deterministic `hash(uv)` — [shader-glsl SKILL.md](https://raw.githubusercontent.com/iart-ai/webgl-animation-skills/main/skills/shader-glsl/SKILL.md)
- zocomputer/skills has a `threejs-shaders` skill (Three.js shader materials). nexu-io/open-design `shader-dev` mirrors MiniMax — [web search results](https://github.com/zocomputer/skills/blob/main/External/threejs-shaders/SKILL.md); [open-design shader-dev](https://github.com/nexu-io/open-design/blob/main/skills/shader-dev/SKILL.md)
- Remotion compatibility path already installed: `effects.md` documents WebGL2 effects via `createEffect()` ("compile/link shaders in setup()… upload source in apply()") and says to enable WebGL/WebGPU during renders — local file `/home/user/.claude/skills/remotion-best-practices/remotion-markup/effects.md`
- I found no skill that combines Remotion with GLSL or p5 shaders — [web search](https://www.skills.sh/oakoss/agent-skills/remotion)

### Inferences
- gokayfem output (a `mainImage(out vec4, in vec2)` fragment) becomes Remotion-ready with a small adapter: prepend uniforms `iResolution`, `iTime = frame/fps`, `iFrame = frame`, and run it as a WebGL2 `createEffect()` with no source, or as an R3F full-screen quad. This adapter is a good candidate for a studio template (e.g. `templates/shader-field/`).
- gokayfem's bundler and checker are executable scripts. The checker needs glslangValidator, which may not be installed, so ask before installing it. The library itself (GLSL text) is usable as documentation without running anything.
- GPU at render time: heavy raymarching (clouds, ocean) can be very slow under SwiftShader in headless Chromium. Use `gl=angle` per the Remotion docs and keep shaders cheap for 1080p×N-frame renders.

### Gaps
- I didn't open gokayfem's SKILL.md body or scripts to list exactly what they execute, or whether they make network calls.
- I didn't measure GPU or render-time performance.
